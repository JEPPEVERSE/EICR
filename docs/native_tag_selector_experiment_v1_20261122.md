## 1. 修正后的研究问题

在保留 MRAgent 的静态记忆组织、问题解析、key 映射、事件读取、动态工具探索与回答流程的条件下，能否用下游证据驱动的廉价评分器替换部分 LLM tag 评分调用，从而改善完整请求的质量—成本表现？

## 3. 唯一允许替换的接口

建议在两个原生评分调用点引入同一接口，默认实现仍执行原 LLM 调用。禁止通过拦截所有聊天请求、模糊匹配提示词来替换，避免误伤事实重排或回答调用。

```python
score_tags(context_text, key_id, ordered_tag_ids, stage, graph_scope)
    -> {"tag_scores": {native_tag: score_in_0_1}}
```

输入 `stage` 为 initial 或 expansion。`context_text` 初始阶段是原函数实际传入的问题，扩展阶段是原函数实际传入的事件文本。接口使用原生 tag 名称或稳定映射，不生成新 tag、不改变候选 tag 集合及其顺序。记录 owner/snapshot/key 作用域，拒绝跨快照读取。

实验模式：

- `native`：两个位置都调用原有评分器。
- `cheap_initial`：仅初始位置替换；扩展位置原生。只在需要归因时运行。
- `cheap_all`：两个位置都替换，是预定方法主臂。

tag 数未达到原生评分触发条件时，继续原生直通，不能为了让模块生效而新增筛选。空 key、空 tag、时间专用路径的绕行也遵循原逻辑。

**保留清单：** 图所有原生索引和边、事件/原文/来源/时间元数据、关键词抽取与映射、初始事实选择、topic检索、工具 schema 与执行器、已读状态更新、去重、循环提示、模型参数、停止/最大轮数、回答格式及引用语义。

**本轮不加入：** 自建 tag–tag 图、PPR、委员会、问题需求分解、gte-rerank-v2、2,000-token 自建证据包、动态入口预算、额外答案 judge 修复循环。旧 EITR 代码可用于资产检查和计费，但不得替代原生读取或回答。

## 4. 廉价评分器的最小可执行定义

### 4.1 作用域与表示

令原生图中沿 `(k,t)` 可读取的事件集合为：

\[
E(k,t)=\operatorname{native\_event\_ids}(k,t).
\]

表示为这个事件集合的向量行视图：

\[
X_{k,t}=[x_e]_{e\in E(k,t)},\quad \|x_e\|_2=1.
\]

不复制每个 tag 下的向量：全局事件向量表加 `(key,tag)→event IDs` 索引即可。表示层按完全相同的来源ID集合合并重复计分行，避免重复重写造成多票；这只是评分视图，**不删除或合并原生图事件、不改原生工具返回**。多来源事件以排序后的完整来源集合标识，不能仅取第一个来源。

优先复用原生事件检索使用的 embedding，保证查询与事件模型、维度、归一化及输入文本身份可核查。原生向量可能编码的是重写句，而工具返回原文；两者的对应关系必须记录，不能将其描述成同一文本。如果已有缓存无法确认身份或拿到相容的查询编码器，停止该索引的复用，先统一补齐所有评分行并记录新增离线成本，不能混用旧新模型。

不能直接复用旧 matrix pilot 的 text-embedding-v4 向量与另一原生查询模型向量做 cosine。

### 4.2 固定一个原始评分规则

为避免重新展开表示搜索，本轮只用来源去重后的 top-3 平均相似度：

\[
u_e=\max(0,\cos(z_c,x_e)),\qquad
r(c,k,t)=\frac{1}{m}\sum_{e\in\operatorname{Top}_m(E(k,t),u)}u_e,
\quad m=\min(3,|E(k,t)|).
\]

空集合返回0。它是固定的轻量启发式：比单条 max 少依赖一个极值，但不代表证据互补、充分性或同一事件概率，也没有保证比 max 更优。本方案不因主实验成绩改为 max、均值或学习式 attention。top-3 不是本文预先声称的创新贡献；贡献必须由替换后的端到端结果和后续最小消融证明。

仅计算当前合法候选 `(key,tag)` 对涉及的事件并共享重复点积，不扫描每个快照全部 tag。初始评分上下文若与原生已有问题向量输入完全一致可直接复用；否则计算相应向量，不能为了省账偷换上下文。扩展阶段同理，事件文本已有相容向量才复用；新请求成本必须计入。

### 4.3 保留原生分数语义的适配

原始 cosine 分数不能直接套用原生0.7阈值，也不能把 cosine 经随意缩放后称为概率。先在独立开发集记录原生评分响应，以原生 LLM 分数为教师，拟合单调分段映射：

\[
\hat g_s=\arg\min_{g\ \mathrm{nondecreasing}}\sum_{r\in D_s}\frac1{|T_r|}
\sum_{t\in T_r}[g(r(c_r,k_r,t))-y_{rt}]^2,\quad
\hat y=\operatorname{clip}(\hat g_s(r),0,1).
\]

使用确定性的 isotonic regression/PAVA；每次评分请求总权重相同，避免大tag列表支配拟合。initial/expansion分别拟合，前提是该阶段至少20次有效评分调用且覆盖“零分、0至0.7、≥0.7”三个区间；不足时使用合并映射并明确记录，合并仍不足则本轮不进入付费主比较。开发题量上限16题，不能按新题输出不断增加校准样本。

映射目标是**模仿原评分尺度以兼容原生分支**，不是学习答案正确性。不得使用gold答案、gold来源、主评估题的原生分数拟合。输入超出校准范围时夹到端点；保留插值约定、相等分数的排序规则及浮点精度。原来的非零筛选、TAG_LIMIT和≥0.7提前读取分支不改。

同时报告零分/提前读取集合的数量与教师差异；isotonic可能产生大量同分或不输出精确零，这属于真实选择器行为，不能暗中补一个新阈值。它若导致不可接受的泛化或成本问题，按结果停，不用主评估集修映射。

该校准是一个很小的评分尺度适配，不是无训练方法。论文必须如实说明教师调用、校准数据与成本。保留训练分数不是为了在线依赖原生分数；主臂绝不能先调用教师再称为省掉教师。

### 4.4 失败处理

图scope或向量身份错误是实现错误：预检失败，禁止继续实验。在线编码器不可用时，可走一次原生评分作为明确 fallback，记录次数、原因与完整费用；不得静默返回全零或删除本题。fallback超过10%的触发评分调用时，判定适配可靠性不足，不据此宣布算法无效或成功。native和cheap共享同样的底层网络重试政策，完整保留全部attempt。

## 5. 三阶段执行；先查价值，再跑小实验

### Stage A：只读审计、原生插桩与成本空间

先利用已有原生完整trace；旧受控工具运行不能冒充原生。如果现有日志无法分出tag评分，用最多16道已使用开发题补充原生插桩运行。这些题同时用于后续校准，不进入主评估。

需要得到：初始与动态tag评分触发率、每题调用次数、tag列表大小、tag评分API费用占完整请求费用比例、延迟占比、提前读取次数、下游探索费用及失败率。所有题目报告总体占比，同时报告触发子集，不能只挑触发题声称普遍省钱。

设基线总成本为 C，拟替换评分成本为 C_tag。在其他轨迹不变且新选择器免费的理想化条件下，纯替换节省上限约为 C_tag/C。这是条件性成本空间估计，不是轨迹改变后的硬上限。

**预设继续条件：** 任一阶段存在实际触发，且完整替换涉及的tag评分平均API费用占比≥10%。低于10%时暂停本主线，不为达到目标去删除后续循环或扩大替换范围；若想研究更大范围的工具决策，另立假设。美元/人民币费率未能可靠固定时，该门槛保持未判定，可报告同模型token占比作诊断，但不能替代经济结论。

### Stage B：接口与校准验收

最多16道已使用开发题；固定样本清单后运行native，收集同一执行轨迹的评分上下文、key/tag候选和教师响应。用这些完整记录校准，检查两个位置触发支持。shadow模式下计算cheap选择，不改变原生状态；用于观察top-tag集合、提前读取集合和来源可达性差异。

shadow结果只评价同状态的局部替换，不能代替端到端质量/费用。动态主臂访问的状态可能不同，必须在Stage C真实执行。

进入Stage C前必须通过：

1. 插桩版native与冻结本地native在固定外部响应回放下，逐工具参数、返回事件/文本、读状态、初始回答输入一致。
2. cheap接口回放原生tag分数时，完整轨迹与native一致，证明适配层没有偷偷改变原函数分支。
3. 同一个 `(key,tag)`、相同上下文/状态下，两臂原生工具输出逐字节或规范化结构相同。
4. 同名tag跨key、跨owner不能混读；空/小tag列表不额外筛选；重复来源只影响评分视图。
5. ≥0.7提前读取边界、TAG_LIMIT截断、零分排除、动态阶段使用事件文本、查询缓存身份、调用账完整性都有可复核测试。
6. 所有非tag聊天请求的路由不变；原生topic/persona/time/context工具可执行；不接入旧重排或原文装包代码。

## 6. 指标与判分

### 6.1 质量主指标

主指标为按题平均的语义正确率，每次完整运行都评分；无答案和无法解析答案计失败，保留分母。两次重复先在题内平均，再跨题汇总。报告每题N/S胜平负、会话/题型拆分、超时、工具失败、回答格式失败和重复波动。

严格rubric显式要求回答问题所要求的全部项目，避免“Yoga, strength training”只答strength training被任意判对。对新增无依据内容、错误日期、部分答案、合理替代表达分别写规则，用旧开发错例验收rubric后冻结。strict为主，原MRAgent宽松rubric为敏感性结果，不挑有利口径。两臂使用同样的judge模型与提示。

评分者不见方法名、成本、轨迹。相同question/reference/answer文本同rubric复用判断。对所有跨臂分歧、partial credit边界、时间解释和已知gold疑点，输出隐藏臂名与随机顺序的复核包。自动judge再次调用只能视为敏感性检查，不能冒充人工盲审。若人工独立复核未完成，报告原始结果和对称处理的上下界；结论依赖争议样本则判不确定，不宣称成功/非劣。

不把旧矩阵系统的source_id字符范围合同套到原生回答上。按原生输出合同检查；答案文本正确、原生证据来源有效、来源支持答案分别记录，不能混成一个分数。

### 6.2 成本与延迟主指标

完整请求费用分项：问题解析、初始事实选择/重排、初始tag评分、动态tag评分、工具循环推理、回答、新增在线embedding及所有重试/fallback。若循环中同时承担最终回答，不人为拆出不存在的独立调用；以真实请求分类。

费率绑定provider、model、endpoint、币种、生效日期、输入/输出及缓存价格。币种统一；不把embedding/rerank/chat token相加后套同一价格。不明usage保持unknown，不能当零。只要存在未计价请求，整体费用均值就不完整；若能从请求/响应与费率给出保守上下界，则只有最不利边界仍满足节省门槛才允许继续，否则判不确定。5%的缺失比例上限不代表允许简单删掉这些请求计算节省。

主成本统计为全部请求尝试的平均费用及逐题配对差值；另列成功请求条件下费用，不能剔除失败来制造省钱。模型少回答、提前放弃导致成本下降，不视为降本保质。

延迟独立顺序测量、臂顺序交错；记录完整wall time、每阶段HTTP/CPU时间、失败与超时。只在相同测量条件下比较；小样本p95仅描述，不作为尾延迟保证。工具数和轮数是解释成本变化的中间指标，不代替真实费用。

新增离线支出为额外向量构建、索引及教师校准，和原生共用的已有建图成本分开。若每题节省 s>0，新增一次性成本 B 的回本量为 ceil(B/s)；若s≤0则无正向回本。另报告快照更新后的重建频率，不能默认离线费用永不重复。

### 6.3 机制诊断指标

- 每阶段评分触发率、替换调用数和fallback率；未触发题是边界检查，不以其稀释后的总分掩盖触发子集损失。
- 评分候选 `(key,tag)` 数、选中数、提前读取数；tag输出本身不能叫“正确tag”，除非有独立标注。
- 下游访问事件/来源、上下文/时间/topic/persona工具调用、轨迹长度和重复读取；标注来源召回仅作为诊断。
- 分解总费用差：节省的评分费用＋新增embedding/校准摊销＋下游探索费用变化。
- 对教师已访问状态的shadow比较与cheap真实到达的新状态分别分析，不能把前者当成后者。

## 7. 运行前冻结的继续、停止与不确定规则

以下是资源投入门槛，不是统计显著性或非劣效界限。Stage A/B通过后，在Stage C开跑前将数值、价格表、样本、源码和校准器写入机器可读协议，不随结果改变。

**进入确认轮需同时满足：**

1. 方法完整请求平均API费用至少下降15%；新增一次性支出与回本量另列。不得只报告tag评分调用下降。
2. 32题按题平均的严格正确率不下降；任何人工复核未决样本的合理对称处理都会使这一结论反转时，判不确定。
3. 至少3/4会话出现费用下降；不以一个异常昂贵请求单独解释全部节省，报告删去最高成本一题后的敏感性分析，但不删去主表中的题目。
4. 方法运行失败率不高于基线；fallback≤10%的触发调用；费用/usage缺失不超过请求数5%，否则完整经济结论不成立。
5. 适配一致性、分母完整性、模型/图身份、计费与曝光审计通过。

没有触发tag评分或Stage A显示其费用占比太小：停止该成本主张，不扩大替换边界。适配失败或评分不确定：记为不确定，优先说明原因，不把它归为数学方法失败。适配有效、费用没有实质下降或可靠质量损失：停止当前评分器，不在主评估题上换公式/校准阈值。

若S有成本收益但轻微质量损失，只能记录质量—成本折中，不按本方案进入“保质降本”的确认轮；若想改变研究目标，需要显式重定主张并使用新的确认集，不能运行后放宽门槛。

## 8. 确认轮与第二baseline的进入条件

Stage C通过后，冻结全部实现、校准器、评分rubric和配置，在另一批32道未用于校准或Stage C的题上确认。优先增加未用会话；如果复用会话，披露共享图，不称为跨用户泛化。确认轮仍完整两次重复，只运行N/S，不增加模块。

确认轮也满足同一继续条件，才进入第二个图记忆baseline。第二baseline选择条件：

1. 有明确、付费且可替换的语义入口评分步骤，而不是仅有同名“tag”字段。
2. 原生入口能映射到可审计下游证据；可以建立表示而不重构底层图。
3. 可以保持该系统原有的读取、工具探索和回答逻辑；无需为了接入本方法加入新的retrieval pipeline。
4. 入口身份、候选空间和分数语义可以定义清楚；现有分数阈值需要独立开发校准，不能直接照搬MRAgent的0.7映射。
5. 原生基线能够用同一资产、模型和协议完整复现，且入口选择确有经济优化空间。

每个baseline只适配接口、身份与分数尺度；核心原始评分规则不根据该baseline测试结果重新设计。第二baseline必须独立报告原生/方法端到端结果，不能横向比较两个不同系统的绝对正确率来证明模块泛化。

只有这时再添加一个必要的表示消融：在同一原生接口下，使用 `(key, tag文本)` 的简单embedding选择器对照下游证据表示。否则即使N→S成功，也只能证明便宜替换有用，尚不能证明下游证据矩阵优于更简单的标签文本。该消融不进入首轮最小矩阵，不能在成功前扩展十几级梯子。

## 9. 实施产物与完成标准

建议新目录 `artifacts/native_tag_selector_v1_20261122/`，与旧matrix实验完全分开。拟新增小型selector接口、原生两个调用点的明确接线、原生trace计费钩子与冻结runner；不重写原生agent。

交付清单：

- `scope.md`：替换位置、保留清单、上游归属、本地diff及非复现限制。
- `runtime_manifest.json`：原生源码/配置/本地修改/embedding身份/工具schema hash。
- `calibration/`：开发题、原生评分请求与响应、权重、映射模型、缺失阶段处理及教师费用。
- `protocol.json`：模式、问题排除/采样、分层、重复、模型、价格、调用上限、随机顺序和决策规则。
- `runs/`：每次完整执行的原始响应、工具轨迹、tag决策、读状态、费用、时间和失败。
- `grades/` 与 `adjudication/`：盲评、原始与复核分数分开、争议敏感性结果。
- `checks/`：native恒等回放、selector透传回放、工具读取不变、隔离、预算与调用账校验。
- `analysis.json` 和报告：总体/触发子集质量、费用、会话配对、离线摊销、机制分解和明确继续/停止/不确定结论。

**适配完成的定义不是“能输出答案”，而是“能证明除了tag评分响应及其自然后果，未替换原生图读取与探索语义”。** 验收通过再做Stage C付费实验。

## 10. 资源安排与边界

建议依赖顺序：1）原生快照与Stage A成本审计；2）小接口和恒等回放；3）开发校准与Stage B；4）Stage C小实验与报告；5）仅在通过时做确认轮；6）再选择第二baseline。以门槛而不是日历推动，不承诺几天内获得正结果。

本轮最有价值的正结果是：相同原生系统内，替换廉价入口评分确实减少完整请求成本，且未在诊断集观察到质量下降。它仍不足以支持正式非劣效、跨数据集普适性、发表概率或新颖性结论。最有价值的负结果是明确定位：优化空间太小、选择器不可靠、动态探索抵消节省，或下游本身成为瓶颈；不再用不断改图与加模块掩盖这些边界。
