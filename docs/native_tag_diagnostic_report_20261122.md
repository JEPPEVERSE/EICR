## 校准、影子失败与修复

开发阶段记录 36 次初始评分、18 次扩展评分。严格验证完整候选响应后，分别保留 17、14 次教师调用；其余 23 次不用于拟合。两个阶段各自都不足 20 次，按预注册规则采用 31 次调用的合并映射，覆盖零分、低分和 ≥0.7 三个区间。

影子批次计划 16 次，前 4 次完成，第 5 次（conv-41-qa058）在统计可达来源时遇到模型新增的 `(Maria, Plan)` 而抛出 KeyError；后 11 次没有发出调用。失败及全部已付费尝试保留在原始账本。影子验收没有通过，也没有把离线修复结果改写成真实验收通过。

修复只涉及诊断与回放：未知输出 tag 按原生读取语义具有空可达边，并显式记录；候选合法性预检仍严格执行。回放响应对象补齐 SDK 的 `exclude_none=True` 序列化语义，以免空字段进入下一轮请求。新增两项回归测试，最终测试结果：**345 passed，6 skipped**。

用 5 个已发请求的真实响应作为离线 fixture，在同一进程内生成原生参考，再对修复后的影子路径做严格请求回放；5/5 的请求、工具轨迹、读状态和答案均与该参考一致，包括产生 `Plan` 的失败案例，新增 API 调用为 0。历史原生检索输出在不同进程中出现排序差异，因此不声称离线 fixture 的输入逐字节等于历史付费输入；这项验证不能替代新的真实影子验收。原来的协议、收费请求和判分没有重新封装为成功。

使用公开且此前检查过的会话和共享图，不是新用户或零曝光测试。主样本按固定 hash 分层抽取并排除历史 ID/文本；本轮未查看主臂输出。当前执行依赖包括 openai 3.57.0、sentence-transformers 6.3.0、tokenizers 0.23.3；后者不同于旧 pilot extra 的 0.22.2，两个任务不能混称为同一依赖环境。
