# EITR 证据委员会修改与验证报告

2026 年 11 月 19 日 · LoCoMo `conv-44` · R_cue · 2,000 token 证据包

本轮要回答两个不同的问题。第一，把图支持度乘在整条证据的收益上，会不会压低有用来源的排名？第二，取消乘法以后，按照已读证据动态奖励相关 cue 的新证据，能否再找回更多来源？两者分别由 `P4` 对 `P4_no_support`、`P4_no_support` 对 `P4_active` 的配对比较回答。

## 修改及验证范围

`P4_active` 复用原有入口、tag 图和候选动作。图路径支持度仍参与候选生成。证据包的共享预算阶段按整题相关性、覆盖增量和交互增量排序。每一步只看新加入的 atom，成本按完整包重渲染后的 token 增量计算。

对每对 cue group，去掉两个组共有的 seed tag，取两端剩余 tag 之间最多三条最高分正权边的均值。双向边只计一次，每行除以 `max(1, 行和)`。这样，两个组映射到完全相同的 tag 时无法彼此投票，单条很弱的边也不会被放大成 1。矩阵只访问本题已接纳的 seed 行。

设已选证据的逐 cue 最大相关性为 `C`，候选把第 j 个 cue 的最大相关性提高 `d_j`。普通覆盖收益是 `mean(d_j)`。交互收益是 `mean(d_j × (A C)_j)`。候选每花一个新增 token 的收益按下式排序。本轮 `η=0.5`，`L=128`，`λ=0.15`。零交互时可精确退回原有 no-support 评分；已读证据更新 `C` 后，才重新计算 `A C`。这轮只引入一个可测的变化，探索配额与来源新颖性项留待有独立证据时考虑。

```text
priority = [η × Σ(new_atom_tokens × whole_question_relevance)
            + (1−η) × L × (coverage_gain + λ × interaction_gain)] / max(1, added_tokens)
```

测试覆盖了重复映射、未入选的 seed、覆盖状态变化、零权重对照和运行记录回放。使用本地 MRAgent checkout 后，全套 147 项测试通过。早期原型曾在交互关闭时也缩放覆盖权重，造成对照漂移。该公式已经修正，早期 `committee_v3`、`committee_interaction035` 等探索目录不用于本报告；正式汇总只读取 `active_final015` 和 `active_final035`。

## 实验口径

20 道冻结题来自一段对话，共 37 个「题目—标注来源」配对。20 题使用同一批预存的规则前端 mentions，逐题验证同配置下各臂候选池哈希一致。宏平均来源召回先按题计算，再对题取平均；全部命中要求该题所有标注来源均出现在包内。只要出现该来源的文本跨度，就算命中。该指标不判断是否包含足够的回答信息。权重 0.35 是在同一开发样本上的敏感性检查。本轮未调用回答或评分模型。

## 结果

| 调度方式 | 包内来源宏召回 | 全部命中 | 命中来源配对 | 平均证据 token |
|---|---:|---:|---:|---:|
| P3 整题相关性 | 43.75% | 8/20 | 11/37 | 1,972.85 |
| P4 支持度乘法＋覆盖 | 42.50% | 7/20 | 10/37 | 1,975.70 |
| P4_no_support 覆盖 | 48.75% | 8/20 | 13/37 | 1,972.75 |
| P4_active，λ=0.15 | 48.75% | 8/20 | 13/37 | 1,972.75 |
| P4_active，λ=0.35 | 48.75% | 8/20 | 13/37 | 1,971.75 |

候选池来源宏召回为 84.58%。取消支持度乘法后，包内来源宏召回比旧 P4 高 6.25 个百分点，比 P3 高 5 个百分点。相对 P3 的逐题结果是 2 胜、18 平、0 负，完整命中题数相同。原有三个对照在主配置上的 60 个证据包哈希全部复现。两套权重各抽取 qa015 做逐步回放，矩阵、选择和证据文本均通过校验。

λ=0.15 时，20 题都在共享预算阶段选中过交互收益为正的动作，但 20 个最终证据包与 P4_no_support 逐一相同。λ=0.35 只改变 qa059 的包，两种方法仍都命中 D12:1。因此不能把相对旧 P4 的提升归给新增交互，也不能据此推断 API 用量、延迟或回答正确率改善。

## 失败题复核和方法判断

qa015 问 Audrey 和 Andrew 养狗时共同遇到的困难。规则前端使两条标注来源中的 D7:8 进入候选池，D10:5 未入池，四种调度都没有将 D7:8 选入包。单独复用此前真实 LLM 提取的三个入口（dog ownership、Audrey、Andrew），D7:8 与 D10:5 均可达，旧 P4 只选到相关的非标注来源 D11:4，而 no-support 与 active 均未选中这三条。这两次回放区分了入口带来的可达性变化和同池排序遗漏。

公式本身解释了一个限制。当一段文字已经把人物名的匹配分推高，下一段真正描述其遭遇的文字即使补足了答案，也可能没有提高任何 cue 的最大匹配分。此时所有 `d_j` 都为零，调大 λ 也无法使这段文字获得交互收益。这个反例界定了设计的能力边界，具体漏选还取决于整题相关性、竞争动作和增量成本。

工程上推荐把 `P4_no_support` 作为下一轮正常问答的廉价调度基线。历史 `P4` 和实验 `P4_active` 仍可显式调用。支持度乘法的负面结果来自一个对话的小样本，去乘法后的质量与成本仍需跨对话、同回答器的配对评估。现阶段缺少把 cue 交互列为论文独立增益的依据。
