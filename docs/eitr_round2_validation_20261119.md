# EITR 第二轮小规模验证 · 2026-11-19

去掉支持度乘法在上一段对话带来的召回提升，未在两段新对话中复现。固定权重 0.15 的交互项与去乘法版本再次逐题输出相同证据包。依据两轮数据，可以暂时优先使用 P3 作为同池调度基线。对完整探索系统的成本和问答质量仍缺有效对照。

## 样本与协议

在 LoCoMo `conv-41` 与 `conv-42` 上，每段对话从类别 1–4 各取 3 题，只纳入有参考答案、来源完整落在本快照内的题。每层按固定哈希排序取样。单独预选其中 4 题做真实问答，两个对话各 2 题，四个类别各 1 题。图结构、2,000 token 预算、模型和交互权重沿用上轮设定。检索对照共用规则前端，真实问答使用百炼 `qwen3.5-27b` 提取入口、回答和盲评。参考标签在评估时读取，答案质量比较共用同题同证据包的输出。两轮的样本用途不同，本报告单列本轮结果。

在线 token 按单臂独立部署核算，包含入口、探索、回答和有 usage 的失败调用，盲评费用另计。P0、P3、no-support、active 答对的是同两道 conv-42 题。John 和 Maria 共同做过哪种志愿活动这道题，所有系统都未答出流浪者收容所。四题不足以检验非劣效，也无法确定举出的单次回答错误是否会稳定复现。

P4 在 conv-42-qa166 首答给出的引用超出可见跨度，按首答失败计入。保留原始失败记录，沿用已完成的候选和答案，仅补齐未完成的回答与盲评，该失败答案未重抽。P5 四次均记录 `native_loop_error`，随后回答器从当时的证据包生成最终答案。退出日志中两题请求未注册的 `answer` 工具，一题请求未注册的 `mode` 工具，另一题最后一次工具模型调用记录为 error、输出 token 达到 2,048 上限，无法从该记录确认更细的根因。因此 P5 行仅描述本轮失败轨迹的实测开销。验证降本主张前应先获得循环正常完成且工具契约有效的对照。
