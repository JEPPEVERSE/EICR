# EITR 16 题真实开发验证报告

2026-11-19。代码固定在 `c024d8ca57224296ff9d2ff35916c7a948a90a6f`。本轮未改算法、阈值、提示词或预算，未替换题目，未重试挑选答案。

## 协议

两个会话 conv-41/conv-42，各四类问题，每个“会话×题型”两题，共16题。按预先固定的 salted hash 选择，排除之前四道真实验证题；这些题此前已做过离线诊断，因此是开发验证，不能当作独立测试集。四类为数据集 category 1–4：多跳、时间、开放域和单跳，各4题。

四臂共享 MRAgent 风格关键词→key→tag 前端、静态图、Qwen3.5-27B 回答、2000-token 原文预算和500-atom候选上限。P3 / C_rerank / C_mmr 逐题严格同池；PPR 单独改变候选生成。MMR与精排共享相同语义分数；同问题同证据包复用答案。精排使用真实 `gte-rerank-v2`。

四臂分别是：P3 原 BM25 贪心；C_rerank 专用语义精排；C_mmr 精排加保守 MMR；C_ppr_rerank 个性化 PageRank 扩展加精排。完整原生 MRAgent/P5 未参与，不能据此给出对原生 MRAgent 的非劣效结论。

两个会话并发运行。问题输入不含答案或 gold sources；labels 只进入检索后的分析与独立盲评。评分模型相同且看不到实验臂名称与成本。宽松和严格口径分别记分，不混合。

## 结论与建议

本轮给出了比前次两题 smoke 更有信息量的正向信号：固定相同候选池、入口和预算，语义精排让最终来源宏召回增加14.375个百分点，严格答案增加2/16，配对为2胜0负。新增答对的两题均为多跳：

- `conv-41-qa052`，问谁给Maria写过感谢信。P3只回答Cindy，精排补齐Laura与Cindy；标注来源由1/2变为2/2。
- `conv-42-qa056`，问两人都喜欢哪种动物。P3回答证据不足，精排回答turtles；标注来源由0/2变为2/2。

这支持“池内排序确实是一个可改进瓶颈”，但收益来自成熟语义reranker，尚不能证明原委员会算法或tag表示的独立贡献。四次来源召回改善只转化成两题答案改善，也说明来源可见性不能替代回答质量。

不应据此把所有额外模块一起保留：本轮MMR在16/16题证据包完全相同，没有可观察增量；PPR使候选宏召回92.19%→96.88%，但最终宏召回76.875%→73.75%，答案与纯精排相同。建议后续主要保留P3与C_rerank这条最小对照，MMR/PPR作为已经实现的诊断开关，不加新委员会、也不为本轮题目继续调阈值。

仍需区分三类剩余问题：

1. **候选与排序的尾部遗漏。** C_rerank仍有6个question/source对在候选池中但未被选中，另有5个在候选阶段丢失。`conv-41-qa064`、`qa050`是开放式属性/职业推断，不能只用局部事实相关性保证完整。PPR补回其中若干候选，但其重排位置仍靠后，未转化为答案收益。
2. **回答推理与标注质量。** `conv-42-qa022`已召回May 2022确认第三个剧本的证据，模型却把February的“another one”当作第三个剧本开始时间，答成February。`conv-41-qa048`的原文会话时间是31 July 2023，gold写作``The sunday before 3` July 2023``，存在缺字/日期不一致疑点；模型给出的July 23也存在相对日期解析疑点。按原gold评分保留为错题，未自行更改日期或剔除；这类题需要独立标注审计，不能全部归因于图或排序。
3. **回答接口合同。** 语义精排14/16回答合同有效，严格正确且合同有效8/16，低于仅看文本的10/16；source_id复制整段标题是具体可修复的工程问题。后续可在另一版本明确标题与JSON citation字段的对应关系，或通过不改变证据的结构化引用选择来解决，再单独回归验证。本轮不修答案、不回填分数。

两种judge的分歧集中在`conv-42-qa085`：严格提示将screenwriter/movie writer判为参考filmmaker的可接受表达，MRAgent宽松提示判WRONG，四臂均少一题。因此“宽松提示”不保证每个样本上数值单调上升，实际LLM判分需要保留原始结果并审计边界案例。两套口径都得到精排相对P3两胜零负，主差异未依赖挑选judge。

关于成本：本轮前端两次模型调用平均约36.0秒（HTTP阶段），纯精排服务平均约0.90秒；这些是并发开发实验阶段耗时，非独立端到端比较。前端约4792聊天token/题，重排约11.65万服务token/题，当前没有实际美元降本证据。不能因为去掉agent循环就宣称“低成本”。如果继续主打降本，应先固定服务单价和可比较原生基线、核算前端与重排全成本，再讨论候选压缩或前端缓存；不要牺牲本轮刚得到的多跳来源覆盖。

本轮判断：**有了可复核的工程改进信号，尚无委员会增益、对原生MRAgent非劣效或总体降本证据。** 小样本中保留最简单的有效改动，比继续堆叠无增益模块更合适。
