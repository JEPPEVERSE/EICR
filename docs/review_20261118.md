# 0.1.1 代码复核与修复记录

复核基线：`e3ee6cf`（0.1.0）。2026-11-18。采用静态阅读、最小反例、进程间重载、合成数据回归和本地冻结缓存兼容性检查；没有调用真实问答模型或运行开发集效果评测。

## 确认的问题

| 优先级 | 问题与触发条件 | 影响 | 修复 |
|---|---|---|---|
| P1 | urllib 默认跟随部分重定向，并将 Authorization 放入新请求 | endpoint 返回跳转时，认证头可能发向另一地址；未观察到实际泄漏事件 | 专用 opener 拒绝全部重定向；要求显式配置最终地址 |
| P1 | 结构邻域报告的计数是 NumPy int64，标准 JSON 无法序列化 | `native_topic` 索引在保存前审计/序列化时失败；原测试只覆盖直接索引保存 | 转为原生数值；新增结构索引保存、加载、CLI审计回归 |
| P1 | facts/edges 未检查声明的 owner；拼错 origin 被当作未来来源丢弃 | 跨 owner 记录可能进入图；缺源事实可静默消失，污染数据质量判断 | 检查所有表的 owner/snapshot；先验证原文存在，再做合法前缀过滤 |
| P1 | 诊断与路由只绑定 index，没有绑定问题 | 批处理/缓存复用时可把 A 问题的分数应用到 B 问题 | query map → diagnostics → route → retrieval 逐级验证内容哈希 |
| P2 | 邻域/词面分数对 set 做浮点累加 | 不同 hash seed 可产生末位差异，影响并列排名或精确审计 | 排序后稳定求和；多进程 hash seed 回归 |
| P2 | LLM 返回 `mentions:[null]` 等结构时调用 `.get`；部分 provider 形状/结束原因未覆盖 | AttributeError 直接终止；错误 trace 可能停留在 started；网络错误被误作格式错误重试 | 完整类型检查、统一受控异常、错误状态、传输错误单次降级、响应上限和 usage 白名单 |
| P2 | 同一 source 内先合并来自不同事实的 cue 支持 | 原本没有共同事实的多个 cue 获得虚高 CORE 支持数 | 按实际事实支撑排名；来源并集单列，保留事实 ID 和 origin-only 限制 |
| P2 | 原文预算按明文计数，回答时又把原文 JSON 转义，并发送内部队列归因 | 实际来源表示与预算计数不一致；回答模型能看到方法选择的队列标签 | 原文块原样送入消息，内部归因留在本地，校验引用范围 |
| P2 | 字面扫描与规范化查找不一致；单个 fuzzy scope 候选被升级为 scope | 重复空白/组合字符等造成漏映射；未解决入口可能被隐藏 | 带原始 offset 的规范化扫描；只有唯一精确/别名映射可提升 scope |
| P2 | 选择较短句界后未重新验证 BPE token 上限；极大有限 dense 值直接求范数 | 可使合法输入触发分块失败，或把 dense 单位向量算成零 | 句界候选重新计数；dense 先尺度缩放再归一化 |

另外修复了审计 `status="passed"` 被报告中的 `status="ok"` 覆盖、混合不合法队列被忽略、字符串形式的布尔配置被接受、部分异常 JSON 的 CLI 退出行为，以及策略冻结时保留可变输入引用的问题。

## 验证结果

- 72项测试通过；新增35个回归参数用例/测试，在原37项测试基础上覆盖上述问题。
- 最初加入的18个反例中，15个在旧版失败、3个为既有保护的对照；修复后均通过。
- 同一结构索引在多个 `PYTHONHASHSEED` 的独立进程中成功重新加载并审计。
- 0.1.1 wheel与源码包构建成功；直接从wheel加载CLI完成了结构索引构建/审计，不依赖源码目录中的包。
- 本地冻结 MRAgent 缓存：675 sources、1,623 facts、2,756 cues、8,662条直接关联；结构索引保存与重载成功。当前确定性配置 Y 有44,035个非零值、1,451行事实有结构扩展。该数字是兼容性检查，不是质量指标。
- 同一输入的30-source前缀适配得到37个合法事实，所有 origin 均属于允许集合。此检查验证过滤逻辑，不替数据提供者证明抽取过程从未见过未来信息。
- 重定向与 provider 格式/限额检查使用合成请求和 mock，不向第三方发送密钥或记忆。

## 升级与剩余边界

包版本升级为0.1.1；索引格式 `eicr-index-2`，策略格式 `eicr-policy-2`。确定性邻域与输入校验变化会影响索引身份及并列裁剪；旧版索引明确拒绝加载，旧 policy 降级 ORIGINAL。应从冻结输入重建索引，重新冻结已审定策略，并重新生成 dense manifest；旧文件保留，不自动覆盖。

仍需独立验证的部分：前端抽取完整性、已有 cue 图的关系分辨率、原文实际支持回答的语义正确性，以及未校准路由的效果。当前来源清单/哈希检查是数据一致性检查，不是第三方签名认证；`extraction_prefix_verified` 依旧是数据提供方的声明。本次检查与修复不构成“代码不存在任何其他漏洞”的保证。
