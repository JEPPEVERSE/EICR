# 诊断后的工程修复与优化验证

日期：2026-11-23。依据 2026-11-22 问题诊断报告，依次处理评测复核、共同答案归纳、选择器校准诊断。

**工程修复已落地；答案优化保留为显式候选，尚未切换默认配置。** 两轮开发题验证显示引用格式退化已消除，但答题质量收益还不足以支持全面替换。选择器的排序／覆盖损失尚未解决；本轮没有依据已检查主样本修改公式或阈值。原生默认、冻结实验成绩及 `inconclusive` 决定保留。

## 已实施的改动

| 环节 | 实施内容 | 验证与边界 |
|---|---|---|
| 判分与来源复核 | 新增覆盖全部 128 条运行的来源复核包，去重为 83 项；包含参考来源、引用来源、会话日期和前后两条邻近对话；同时保留 strict、lenient、参考有效性三个待裁定字段 | 隐藏臂名、成本、原分；未填写人工裁定。不是把原有 27 项未决答案直接改分。旧队列和成绩保持原样。 |
| 人工裁定导入 | 校验复核文本指纹、审核者身份字段、证据 ID、分数类型及同文同判；有争议的参考答案不允许静默重判 | 输出独立裁定版本。未解决的参考答案或未填分数仍标为未完成；没有伪造审核者。语义等价但文本不同的答案仍需审核者统一规则。 |

| 可复现验证 | 新增固定最终上下文的配对重放：冻结问题清单、候选版本、请求、源码身份、随机顺序和调用上限 | 同一上下文及输出预算；只允许答案系统提示不同。没有新工具读取，不能当作端到端质量或成本结果。失败调用保留账本与分母。 |

新配置进入运行协议及执行身份检查，无法在原冻结协议下静默启用。未来若更换完整回答器，开发、校准、影子验收和比较应绑定新身份；不能把旧证明直接沿用到新系统。原生 `native` 仍是默认。

## 两轮真实开发题验证

使用之前固定的 **16 道开发题**，每题已有两次原生运行的最终上下文，共 32 个上下文；每轮分别用原生提示和候选提示各重新回答一次，配对随机交错、串行执行。每轮 64 次回答，统一最多 1,024 个输出 token。没有重新运行检索，也没有从主实验错题挑验证样本。

自动评分继续使用原冻结 strict／lenient 文本及相同 DeepSeek 模型，对答案隐藏方法名，精确相同文本复用评分。它不是独立人工裁定；争议规则仍未解决。两轮所有调用均使用之前授权的 DeepSeek endpoint。

| 指标 | 第一轮：原生提示 | 第一轮：v1 | 第二轮：原生提示 | 第二轮：v2 |
|---|---:|---:|---:|---:|
| 自动 strict | 27/32 | 27/32 | 24/32 | 25/32 |
| 自动 lenient | 27/32 | 27/32 | 24/32 | 25/32 |
| 合法引用 ID | 32/32 | 28/32 | 32/32 | 32/32 |
| 调用／回答格式失败 | 0 | 0 | 0 | 0 |
| 输入 token 总量 | 92,616 | 105,896 | 92,616 | 109,992 |
| 输出 token 总量 | 2,346 | 2,326 | 2,299 | 2,240 |
| strict 待复核运行 | 4 | 4 | 8 | 8 |

第一轮发现 v1 四次把 `Time:...` 或 `Conversation_time:...` 元数据当成引用，因此没有启用它。v2 **只在 v1 上追加引用格式规则**，没有依据开发答案增加特定题目的事实；第二轮该格式问题未再出现。两轮原始记录全部保留，没有只展示较好的轮次。

v2 比同期原生多判对一次，差值 +3.125 个百分点，但不能解释为已证明质量提升：其两个正差异来自同一道狗领养时间题，另一个题次出现负差异；时间精度和开放推断仍需要复核。原生提示在两次独立重放中也由 27/32 变为 24/32，提示生成和评分波动不可忽略。两轮并非 v1/v2 的直接配对比较，不能据此单独估计追加引用规则对语义正确率的影响。

v1 输入增加约 14.34%，v2 增加约 **18.76%**；没有新增检索调用，但提示本身并非零成本。完整请求的最终成本和探索行为还需端到端实验。本轮共 **128 次回答调用、106 次自动评分调用，合计 234 次服务商调用**。usage 和逐次账本均保存。2026-11-23 的适用费率没有重新核实，所以实际货币成本保持未知；JSON 中按 2026-11-22 周日历史价格重计的结果只作敏感性参考，不冒充当天账单。

**决策：** 保留 v2 作为下一步候选，继续使用 `native` 默认；不将小样本开发结果宣传为保质降本，不启动确认轮。

## 选择器诊断结果与处理决定

仅使用原 28 次有效开发评分（初始 17、扩展 11）及冻结映射。每折剔除一个开发题的全部请求后重新拟合，再对留出题做局部预测；没有主实验 teacher／gold 参与拟合，也没有新增模型调用。

| 按请求平均的教师集合召回 | 初始，拟合内 | 初始，留题验证 | 扩展，拟合内 | 扩展，留题验证 |
|---|---:|---:|---:|---:|
| 选中集合 | 44.41% | 45.50% | 39.55% | 38.86% |
| 提前读取集合 | 13.25% | 5.00% | 不适用 | 不适用 |
| 零分集合 | 0% | 0% | 0% | 0% |

这测量的是对教师选择行为的模仿，不是答案准确率，也不是主实验 gold 来源召回。初始留题验证有 13/17 次截断同分，扩展为 10/11；两个阶段所有留出预测请求仍有正分下界。

**处理决定：** 本轮未调低 0.7、未改变 TAG_LIMIT、未对 `Project Count` 加特殊规则，也未替换 top-3 公式。现有单调映射无法可靠修复表示层的排序问题；只改阈值会把未验证的额外读取与成本引入系统。新增诊断接口已经可以分离原始排序、映射和同分顺序的影响，下一次表示／校准方案应先明确新假设，在开发集冻结比较，之后用未检查题做确认。

## 使用方法

完整运行的协议 spec 可显式设置：

```json
{"answer_profile": "evidence_complete_v2"}
```

这需要重新冻结匹配的新开发／实验协议，不能修改旧协议文件后直接运行。省略该字段或设为 `native` 使用原生提示。

新增命令（均由 `native-tag --help` 可发现）：

```text
native-tag calibration-audit --records RECORDS --calibration CALIBRATION --out NEW_JSON
native-tag evidence-review-export --runs RUN_DIRECTORY --grades GRADES_JSON --out NEW_DIRECTORY
native-tag evidence-review-import --bundle PRIVATE_JSON --reviewed COMPLETED_JSON --reviewer REVIEWER --out NEW_JSON
native-tag answer-replay-freeze --spec SPEC_JSON --out NEW_PLAN_JSON
native-tag answer-replay-run --plan NEW_PLAN_JSON --out NEW_DIRECTORY
```

重放 spec 包含 `runs`、`question_ids`、`candidate_profile`、`repeats`、`seed`、`max_output_tokens`，以及可选的有来源价格表 `prices`。每个被选问题的所有原始臂和试次都会进入，不能按其答案挑选上下文。单次重放最大 128 个原始上下文、最多两次重放，调用上限写入计划；执行前重新构造计划验证配对及请求一致性。已有输出目录拒绝覆盖。
